## 3. dsh agent output budget (maxTokens)

- **Symptom:** "Output token limit reached" in session `f24335e7`. The turn ended at
  `outputTokens = 11264` = the configured cap, `stopReason: length`, 25261 of 32768 tokens used.
- **Where 11264 came from:** config, not a code default. `adapterDefaults.maxTokens: true`
  only means dsh-llm filled `maxTokens` from the adapter's `defaultMaxTokens`, and that is
  the model entry's own `maxTokens`. The path: `dsh-llm-pi-ai/lib/index.js:672-674` →
  `:1813` → `dsh-llm/lib/index.js:2112`.
- **History of the value:**
  - 09-19 10:39: 16384 → 8192 (backup `settings.yaml.pre_maxtokens`).
  - 09-19 19:57: 8192 → 11264 (backup `settings.yaml.pre_outputbudget`), made by dsh
    session `557eaa95` under the manual invariant `threshold + maxTokens <= contextWindow`
    with thresholdRatio 0.65 (21299 + 11264 = 32563). thresholdRatio was later changed to 0.55.
- **pi-ai already clamps** (`@earendil-works/pi-ai/dist/api/simple-options.js`,
  `clampMaxTokensToContext`, `CONTEXT_SAFETY_TOKENS = 4096`; openai-completions goes
  through `buildBaseOptions`). What it sends is
  `max_tokens = min(maxTokens, contextWindow − estimateContextTokens(ctx) − 4096)`.
  - The estimate here is chars/4, because dsh replays assistant messages with empty usage.
  - Measured on `f24335e7`: 26,664 chars → 6,666 estimated vs 6,803 real (~2% under).
- **Change:** UD-IQ4_XS `maxTokens` 11264 → **28672**. The manual invariant is retired.
  - **Rule:** `maxTokens = contextWindow − 4096` for every entry.
  - flashnext-local: 8192 → **94208** (window 98304).
  - GSQ: **61440** (window 65536).
- **Verified:** headless session `ba2e6801` had `request/header` `maxTokens: 28672`, and
  `restore_8092.log:37` shows `n_tokens = 7614, truncated = 0`. The header records the
  configured ceiling, not the clamped value actually sent.
- **Documented** in `~/dsh-compaction-select/UPGRADING.md`, subsection "Agent output budget".

### Compaction trigger audit

- Single gate: `meter.totalTokens >= floor(contextWindow × thresholdRatio)` checked at
  `agent/pre-step` (`dsh-compaction-select/lib/index.js:1122`); ratio 0.55 from
  `cordis.patch.yml` (threshold 18,022 at 32k, 36,096 at 65k).
- Meter = last call's `usageTokens` (input + cacheRead + cacheWrite + output) plus the
  surface delta since then (`dsh-token-meter` L643-686); otherwise a chars/4 estimate
  plus tool-schema tokens.
- Compaction checks the NEXT request (previous prompt + reply + new tool results), so
  the previous request sitting below threshold is expected (09-23: 11 of 18 below).
- Known small over-count: `usageTokens` includes output reasoning tokens that dsh does
  not send back; bounded to the last step and resets each call. Not fixed.
- Work room per compaction: 32k ~2.4k tokens mean (n=18); 65k 9.6k (n=1).

### Root cause: Xid 8

- The hangs match [llama.cpp issue #27330](https://github.com/ggml-org/llama.cpp/issues/27330):
  CUDA graphs hang the GPU channel on sm_120 — RC watchdog, Xid 8,
  "launch timed out" in `ggml_backend_cuda_synchronize`.
- Reported on Qwen3.8-27B with q8_0 KV cache, driver 595.84+; hangs hit 4–25 min
  into sustained load, more likely with large context and low VRAM headroom,
  with or without MTP.
- Workaround: `GGML_CUDA_DISABLE_GRAPHS=1` — reported 8–14 h stable at a 10–15%
  decode cost, marginal with MTP.
- Issue is open; no fix PR yet.
- Related: [#28581](https://github.com/ggml-org/llama.cpp/issues/28581) — IQ3_S garbage
  output on a 5060 Ti with this same GSQ file; not seen here (the marker and real
  tasks were correct).
- Production now runs with graphs disabled since 19:20.
